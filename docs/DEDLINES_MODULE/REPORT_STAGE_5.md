# Отчёт: Этап 5 — Модуль «Календарь»

**Дата:** 2026-06-23  
**Статус:** ⏸️ Отложён / не входит в MVP  

---

## Что планировалось

Согласно `SPEC.md` (раздел 13, Этап 5):

- **Сетка календаря** — отображение событий по месяцам / неделям / дням
- **Раскрытие групп** — возможность посмотреть детали дублей внутри группы («Вариант 1 — ✅, Вариант 2 — ❌»)
- **Фильтры по категории и программе** — те же 4 категории + фильтр по конкретной программе
- **Показ всех событий** — включая прошедшие (без ограничения `date >= NOW()`)

## Почему отложен

Модуль «Календарь» — это **отдельная большая фича**, выходящая за рамки MVP текущего модуля «Ближайшие события и дедлайны».

Приоритеты:
1. ✅ Виджет «Ближайшие события» (Этап 4) — **готово**
2. ✅ Синхронизация и фильтры (Этапы 1–3, 6) — **готово**
3. ⏸️ Календарь (Этап 5) — **отложён**

Календарь требует:
- Другой UI (сетка/таблица вместо списка карточек)
- Отображения прошлых событий (история)
- Раскрытия `raw_items` (детали дублей)
- Навигации по месяцам/неделям

Это логично делать **после стабилизации** основного модуля.

## Что уже готово для будущей реализации

- **Данные** — `raw_items` (JSONB) уже хранит сырые item'ы каждой группы
- **API** — `GET /api/deadlines/{event_id}` возвращает детали с `raw_items`
- **Архитектура** — `SPEC.md` (раздел 11) описывает требования к календарю
