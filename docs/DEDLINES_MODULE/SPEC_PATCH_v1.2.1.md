## 3. Проблемы и решения

### 3.1 🔴 Название модуля на главной (issue #46)

**Проблема:** `Home.tsx` строка 248: `"Ближайшие дедлайны"` — не консистентно со страницей `/deadlines` (`"Ближайшие события"`).

**Решение:** Заменить на `"Ближайшие события"`.

**Критерий приёмки:** Заголовок модуля на главной = `"Ближайшие события"`.

---

### 3.2 🔴 Кнопка «Все» в заголовке модуля (issue #47)

**Проблема:** Кнопка `"Все"` с `ChevronRight` находится в заголовке модуля. По дизайн-системе кнопка `"Показать все"` должна быть внизу модуля (как у курсов).

**Решение:**
1. Убрать кнопку из заголовка
2. Добавить `"Показать все (N)"` внизу модуля
3. Показывать только если `total > events.length`

**Критерий приёмки:** Кнопки `"Все"` нет в заголовке; внизу есть `"Показать все (N)"` при наличии скрытых событий.

---

### 3.3 🔴 Лишние бейджи на будущих событиях (issue #48)

**Проблема:** На карточках `DeadlineCard.tsx`:
1. `"Выполнено"` показывается при `status === "passed"`, даже если событие в будущем
2. `"N вариантов"` — нет плюрализации (`"1 вариантов"`)

**Корень:** `status` приходит как `"passed"` из Netology API для групп с одинаковым `lesson_id`.

**Решение:**
1. `isPassed` — дополнительная проверка `isEventPast(event)` (дата < сегодня)
2. Функция `pluralize()` для склонения `"вариант/варианта/вариантов"`

**Критерий приёмки:**
- `"Выполнено"` только для прошедших событий
- `"1 вариант"`, `"2 варианта"`, `"5 вариантов"`

---

### 3.4 🔴 Дублирование событий (issue #49)

**Проблема:** Через некоторое время каждое событие дублируется. У дублей появляется бейдж `"2 вариантов"`.

**Корень:** Race condition в бэкенде. Два параллельных `sync`-запроса:
```
Запрос A: DELETE → INSERT 10 событий
Запрос B: DELETE → INSERT 10 событий (теперь в БД 20!)
```

**Решение (многоуровневое):**

**Backend:**
1. Alembic миграция: `UNIQUE(user_id, lesson_id, event_type, title)`
2. Cleanup: удалить существующие дубли перед добавлением constraint
3. `deadline_service.py`: `upsert` (`INSERT … ON CONFLICT DO UPDATE`) вместо `DELETE ALL + INSERT`
4. `deadline_merger.py`: исправить баг `sources` (было всегда `"calendar"`)

**Frontend (защита в глубину):**
1. `useDeadlines.ts`: дедупликация `events` по `id`
2. `useDeadlines.ts`: `silentSyncLock` guard — не запускать parallel sync
3. `Deadlines.tsx`: `setInterval` → рекурсивный `setTimeout` (следующий sync после завершения предыдущего)

**Критерий приёмки:**
- В БД нет дублей по `(user_id, lesson_id, event_type, title)`
- На фронте нет дублирования событий
- Сборка `npm run build` — 0 ошибок
