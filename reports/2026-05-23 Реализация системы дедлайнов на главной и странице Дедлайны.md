## 2. Метод определения и фильтрации дедлайнов по семестрам

### 2.1. Почему это сложно

API Нетологии **не имеет** поля `current_semester: true/false`. В ответе `student_learning/calendar` 45 программ, включая:
- 20 программ бакалавриата (семестры 1 и 2)
- 25 прочих курсов (без семестров)

Программы бакалавриата имеют заголовок вида: `"1 курс, 2 семестр: Философия"`.

### 2.2. Гибридный метод (выбранное решение)

**Шаг 1. Парсинг семестра из заголовка программы**

Регулярное выражение: `^(\d+)\s+курс,\s+(\d+)\s+семестр:\s+(.+)$`

Результат:
- Курс: `1`
- Семестр: `2`
- Дисциплина: `Философия`

Точность: **100%** для бакалавриата (заголовок формируется сервером).

**Шаг 2. Валидация через расписание профессии**

Из API `/backend/api/user/professions/59690/schedule` получены 23 модуля с точными датами:

| Модуль | start_date | finish_date |
|--------|------------|-------------|
| 1 курс, 1 семестр: Элементы высшей математики | 2025-09-01 | 2026-01-31 |
| 1 курс, 2 семестр: Философия | 2026-02-02 | 2026-06-30 |

Это позволяет валидировать: если `finish_date` в прошлом — семестр завершён.

**Шаг 3. Определение «текущего семестра» по дате**

```
Февраль – Июнь     → 2 семестр
Сентябрь – Январь  → 1 семестр
Июль – Август      → каникулы (показываем всё с будущими дедлайнами)
```

Текущая дата (23 мая 2026): **2 семестр**.

**Шаг 4. Правило включения программы**

```
Если НЕ бакалавриат:
    → ВСЕГДА включать (курсы без семестров)

Если бакалавриат:
    → Если parsed_semester == current_semester: ВКЛЮЧИТЬ
    → Иначе если deadline >= сегодня: ВКЛЮЧИТЬ (пересдача/академразница)
    → Иначе: ПРОПУСТИТЬ (прошлый семестр, просрочено)
```

### 2.3. Почему это лучше, чем "просто по названию"

| Подход | Проблема |
|--------|----------|
| Только по названию раздела | Не знаем, завершён семестр или нет. Семестр 1 мог иметь пересдачи в мае. |
| Только по дате дедлайна | Не знаем, к какому семестру относится. Академразница в мае — это семестр 1. |
| **Гибрид: название + даты расписания** | Знаем ИЗ КАКОГО семестра предмет, И активен ли он сейчас, И есть ли пересдачи. |

**Реальный пример:**
- `"1 курс, 1 семестр: Финансовый университет: история и современность"`
- Дедлайн: `2026-05-24` (завтра)
- Парсинг: семестр = 1, дисциплина = "Финансовый университет..."
- Текущий семестр = 2 → обычно бы ПРОПУСТИЛИ
- Но дедлайн в будущем → это **академическая разница** → ВКЛЮЧАЕМ

## 5. Детальное описание изменений

### 5.1. Типы (`frontend/src/types/deadline.ts`)

Добавлены поля в `DeadlineItem`:
- `programName: string` — "Бакалавриат «Финансы и анализ данных»"
- `disciplineName: string` — "Философия"
- `semester: string` — "1 курс, 2 семестр"

Добавлены новые интерфейсы:
- `ProgramGroup` — группировка дедлайнов по программе
- `DeadlineFilter` — `"all" | "normal" | "urgent" | "overdue"`

### 5.2. Реальные данные (`frontend/src/data/realDeadlines.ts`)

Сгенерирован автоматически из `Данные/archive/api_netology_ru_backend_api_user_student_learning_calendar.json`.

Преобразования:
- UTC → МСК (+03:00)
- Парсинг типа задания из заголовка (homework / creative / exam / test / control_work / coursework)
- Фильтрация accepted/waiting_review
- Фильтрация прошлых семестров

### 5.3. Утилиты (`frontend/src/utils/deadlineUtils.ts`)

**Новые функции:**

| Функция | Назначение |
|---------|------------|
| `isOverdueWithinMonth(deadline, now)` | Для главной: просроченные только за последние 30 дней |
| `filterForHome(items, now)` | Комбинированный фильтр: visible + не старше месяца |
| `groupByProgram(items)` | Группировка `EnrichedDeadlineItem[]` → `ProgramGroup[]` |
| `getDeadlineCounts(items, now)` | Счётчики по каждому фильтру (all/normal/urgent/overdue) |

**Изменённые функции:**

`formatDeadline` — убраны дни недели. Теперь только:
- «Сегодня, 23:59 МСК»
- «Завтра, 10:00 МСК»
- «25 мая, 23:59 МСК»

### 5.4. Хук (`frontend/src/hooks/useDeadlines.ts`)

- Заменён источник: `demoDeadlines` → `realDeadlines`
- Добавлен параметр `filter: DeadlineFilter` для страницы «Все дедлайны»
- Добавлено поле `counts` в возвращаемое значение (для кнопок-фильтров)

### 5.5. Карточка (`frontend/src/components/DeadlineCard.tsx`)

- Убраны дни недели из отображения даты
- Добавлен проп `showProgram?: boolean` — показывать ли `programName` сверху
- Сохранена цветовая схема: красный=просрочено, оранжевый=срочно, лавандовый=обычно
