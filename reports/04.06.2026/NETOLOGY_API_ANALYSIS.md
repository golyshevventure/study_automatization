## 3. Сравнение endpoint'ов

| Что нужно | `/student_learning/calendar` | `/programs/{id}/schedule` |
|-----------|:----------------------------:|:-------------------------:|
| ДЗ (task) с дедлайном | ✅ `lesson_task.deadline` | ✅ Дедлайн в `title` |
| Тесты (test) | ❌ **Нет** | ✅ Есть |
| Квизы (quiz) | ❌ **Нет** | ✅ Есть (не найдено в текущих модулях) |
| Вебинары | ✅ `starts_at`/`ends_at` | ✅ Есть |
| Зачёты/экзамены | ✅ (тип webinar, по названию) | ✅ Есть |
| Видео | ❌ Нет | ✅ Есть |
| Тексты | ❌ Нет | ✅ Есть |
| Вложения | ❌ Нет | ✅ Есть |
| Статус `passed` | ⚠️ Только webinar | ✅ Для task/test |

## 5. Выводы

### Что НУЖНО для полного модуля дедлайнов

**Обязательно использовать ОБА endpoint:**

1. **`/student_learning/calendar`** — для:
   - ДЗ (task) с точным дедлайном `lesson_task.deadline`
   - Вебинаров/зачётов/экзаменов с датами `starts_at`/`ends_at`

2. **`/programs/{id}/schedule`** — для:
   - **Тестов (test)** — их нет в calendar!
   - **Квизов (quiz)** — если появятся
   - Дедлайн парсить из `title` (формат `DD.MM.YYYY`)

### Классификация webinar

Тип API — `webinar`, но по `title` подразделяются:
- `title` содержит "**Зачёт**" / "**Зачет**" → Зачёт
- `title` содержит "**Экзамен**" → Экзамен
- `title` содержит "**Консультация**" → Консультация
- Остальные → Вебинар/занятие

### Проблема с task дедлайнами

В `/student_learning/calendar` у 94 task из 155 `deadline` = `null`. У 61 — есть дедлайн.

В `/programs/{id}/schedule` дедлайн у task есть в `title` (парсить regex).

**Рекомендация:** брать дедлайн из calendar (если есть), иначе парсить из title program schedule.

### Проблема с passed статусом

- `/student_learning/calendar`:
  - Для task: `lesson_task.homework.status` — `waiting_review`, `null`, иногда `accepted`
  - Для webinar: `status` — `passed`, `approved`
- `/programs/{id}/schedule`:
  - Для task/test: `passed` — `true`/`false`

**Рекомендация:** для task — OR по обоим источникам. Если хотя бы в одном `passed`/`accepted` — считать выполненным.
