# Профиль пользователя в шапке Home

**Дата:** 2026-05-31
**Контекст:** На странице `Home` (главная страница приложения) отображалась заглушка — хардкод имя "Алексей Петров" и сгенерированный аватар через ui-avatars. Необходимо было отображать **реальные** данные пользователя (имя и фото) из аккаунта Нетологии.

---

## Что сделано

### 1. Расширена таблица `user_sessions` (PostgreSQL)

**Новые поля:**

| Поле | Тип | Описание |
|------|-----|----------|
| `full_name` | `VARCHAR(255), nullable` | Полное имя пользователя (из Netology) |
| `avatar_url` | `TEXT, nullable` | URL аватара пользователя (из Netology) |

**Почему кешируем в БД:** Данные пользователя (имя, фото) меняются крайне редко. Нет смысла при каждом открытии страницы дёргать API Нетологии — достаточно один раз при логине сохранить профиль в PostgreSQL, а затем отдавать из кеша.

**Alembic миграция:** `d7c57cb3d98c_add_full_name_and_avatar_url_to_user_sessions.py`

```bash
cd backend && ../.venv/bin/alembic revision --autogenerate -m "add_full_name_and_avatar_url_to_user_sessions"
cd backend && ../.venv/bin/alembic upgrade head
```

Также обновлён `backend/alembic.ini` — заменён старый пароль с `@` на новый `StudyCore2026SecurePass` (DSN с `@` в пароле ломал парсинг URL).

### 2. `NetologyAuthService` — парсинг профиля при логине

При успешном POST `/backend/api/user/sign_in` Netology возвращает JSON:

```json
{
  "app_options": {
    "user": {
      "full_name": "Никита Голышев",
      "medium_avatar_url": "https://u.netology.ru/backend/uploads/...",
      "email": "golyshevventure@gmail.com"
    }
  }
}
```

**Изменения в `backend/services/auth_service/netology_auth.py`:**

- Добавлен `AuthResult(NamedTuple)` — возвращает `cookies`, `full_name`, `avatar_url`
- Метод `authenticate()` теперь парсит JSON-ответ и извлекает `full_name` + `medium_avatar_url`
- Если JSON сломан — не падаем, просто возвращаем `None` для имени/фото

```python
class AuthResult(NamedTuple):
    cookies: httpx.Cookies
    full_name: Optional[str]
    avatar_url: Optional[str]
```

### 3. `SessionManager` — сохранение профиля в БД

**Изменения в `backend/services/session_service/session_manager.py`:**

- `create_or_update_session()` теперь принимает `full_name` и `avatar_url`
- При обновлении существующей сессии — перезаписываем имя/фото (если переданы)
- При создании новой — сохраняем сразу

```python
async def create_or_update_session(
    self,
    email: str,
    cookies: dict,
    full_name: Optional[str] = None,
    avatar_url: Optional[str] = None,
) -> UserSession:
```

### 4. `auth_router` — endpoint'ы возвращают профиль

**Изменения в `backend/api/auth_router.py`:**

**POST `/api/auth/netology`:**
- Теперь получает `AuthResult` (не только cookies)
- Передаёт `full_name` и `avatar_url` в `SessionManager.create_or_update_session()`
- Профиль сохраняется в БД при КАЖДОМ успешном логине

**GET `/api/auth/me`:**
- Расширен `MeResponse` — добавлены `full_name` и `avatar_url`
- Возвращает кешированные данные из `UserSession` (БД)
- НЕ делает запросов к Netology — только читает из PostgreSQL

```python
class MeResponse(BaseModel):
    authenticated: bool
    user_id: str | None = None
    email: str | None = None
    full_name: str | None = None
    avatar_url: str | None = None
```

### 5. Frontend — `AuthContext` загружает профиль

**Изменения в `frontend/src/contexts/AuthContext.tsx`:**

- Расширен интерфейс `AuthUser`:
  ```typescript
  interface AuthUser {
    user_id: string;
    email: string;
    full_name: string | null;
    avatar_url: string | null;
  }
  ```
- `checkAuth()` парсит `full_name` и `avatar_url` из ответа `GET /api/auth/me`
- Данные сохраняются в `user` state контекста
- При logout — `user` сбрасывается в `null`

### 6. Frontend — шапка `Home` с реальными данными

**Изменения в `frontend/src/pages/Home.tsx`:**

- Удалён хардкод:
  - Было: `<h1>Алексей Петров</h1>` + `<img src="https://ui-avatars.com/api/?name=Alexey+Petrov...">`
  - Стало: динамические данные из `useAuth()`

- Добавлен компонент `HomeHeader()` (внутри `Home.tsx`):
  - Берёт `user` из `useAuth()`
  - `displayName` = `full_name` → `email` → `"Пользователь"`
  - `avatarSrc` = `avatar_url` (из Netology) → fallback на `ui-avatars` с именем

```tsx
function HomeHeader() {
  const { user } = useAuth();
  const displayName = user?.full_name || user?.email || "Пользователь";
  const avatarSrc =
    user?.avatar_url ||
    `https://ui-avatars.com/api/?name=${encodeURIComponent(displayName)}&background=8a2be2&color=fff&size=96`;

  return (
    <div className="px-5 pt-8 pb-6 flex items-center justify-between">
      <div>
        <p className="text-sm font-medium mb-1" style={{ color: "rgba(255,255,255,0.7)" }}>
          Студент Нетологии
        </p>
        <h1 className="text-2xl font-bold" style={{ color: "#fff", textShadow: neonShadowLight }}>
          {displayName}
        </h1>
      </div>
      <img src={avatarSrc} alt={displayName} className="w-12 h-12 rounded-full" ... />
    </div>
  );
}
```

**Fallback логика:**
- Если `avatar_url` есть (из Netology) → показываем реальное фото
- Если `avatar_url` пустой → `ui-avatars.com` генерирует аватар по имени
- Если `full_name` пустой → показываем `email`
- Если `email` тоже пустой → `"Пользователь"`

## Архитектура потока данных

```
Пользователь вводит логин/пароль на Welcome
    ↓
Frontend → POST /api/auth/netology
    ↓
FastAPI → NetologyAuthService.authenticate()
    ↓ POST /sign_in
Netology.ru → JSON {user: {full_name, medium_avatar_url, ...}}
    ↓
AuthResult(cookies, full_name, avatar_url)
    ↓
SessionManager.create_or_update_session(email, cookies, full_name, avatar_url)
    ↓ INSERT/UPDATE
PostgreSQL (user_sessions: full_name, avatar_url)
    ↓
JWT-cookie session_token установлен
    ↓
Frontend получает success=true
    ↓
AuthContext.checkAuth() → GET /api/auth/me
    ↓ SELECT (full_name, avatar_url из БД)
PostgreSQL → {authenticated: true, full_name: "...", avatar_url: "..."}
    ↓
AuthContext.user = {full_name, avatar_url, ...}
    ↓
HomeHeader читает useAuth() → отображает имя и фото
```

## Что делать, если пользователь поменял фото/имя на Нетологии

Текущая реализация обновляет профиль **только при логине**. Если пользователь поменял имя/фото на Нетологии, но остаётся в StudyCore — изменения не подтянутся.

**Решение (если потребуется):**
- Добавить кнопку "Обновить профиль" в настройках
- Или при каждом `GET /api/auth/me` раз в N часов делать фоновый запрос к Netology
- Или при открытии Home страницы раз в день обновлять профиль

Пользователь попросил не нагружать программу лишними запросами — поэтому сделано минимально: один раз при логине.
