## 2. Проблемы и решения

### 2.1 🔴 TS-ошибки сборки фронтенда

**Проблема:** `npm run build` падает с ошибками TypeScript.

**Причины:**
- Отсутствуют npm-пакеты: `clsx`, `tailwind-merge`, `sonner`, `next-themes`, `@radix-ui/react-slider`, `@radix-ui/react-switch`, `@radix-ui/react-tabs`, `@radix-ui/react-toggle`, `@radix-ui/react-toggle-group`, `@radix-ui/react-tooltip`
- Неиспользуемые переменные: `useEffect` в `useDeadlines.ts`, `navigate` в `Welcome.tsx`, `refetch` в `Deadlines.tsx`

**Решение:**
1. Установить все недостающие пакеты
2. Убрать неиспользуемые импорты/переменные (или задействовать их)

---

### 2.2 🔴 Home.tsx — остатки старого API

**Проблема:** `Home.tsx` обращается к старому хуку `useDeadlines("top3")`, ожидает поля `deadlines`, `programName` и т.д., которых больше нет.

**Решение:**
1. Заменить вызов на новый `useEvents("all", 3)`
2. Использовать `DeadlineCard` с новым типом `DeadlineEvent`
3. Удалить импорт старого `useDeadlines`, если он ещё есть

---

### 2.3 🟡 Авто-синхронизация дедлайнов

**Проблема:** Синхронизация только ручная (кнопка «Обновить»). Пользователь может забыть нажать.

**Решение:**
1. **Frontend:** `useEffect` в `Deadlines.tsx` — вызывать `POST /api/deadlines/sync` при первом входе на страницу, если данных нет или `staleTime` истёк
2. **Frontend:** Интервал — `setInterval` с периодом 30 минут (1 800 000 мс) на странице Deadlines, с cleanup при unmount
3. **Backend (опционально):** APScheduler / Celery — фоновая задача для активных сессий

**Выбранный подход:** начать с frontend-интервала (проще, не требует новых зависимостей).

---

### 2.4 🟡 useDeadlines.ts — неиспользуемый хук

**Проблема:** Файл `frontend/src/hooks/useDeadlines.ts` существует, но его импорты вызывают TS-ошибки (неиспользуемые переменные). Новый модуль использует `useEvents.ts`.

**Решение:**
- Удалить `frontend/src/hooks/useDeadlines.ts` (legacy, больше не нужен)
- Проверить, что нигде не осталось импортов из него

---

### 2.5 🟡 Пагинация (backend ready, frontend missing)

**Проблема:** API поддерживает `offset` + `limit`, но фронтенд не использует. При большом количестве событий список будет длинным.

**Решение:**
- Добавить "Загрузить ещё" внизу списка Deadlines.tsx
- Или бесконечный скролл через `useInfiniteQuery` (react-query)

**Приоритет:** низкий, т.к. сейчас событий ≤ 100.

---

### 2.6 🟢 Фильтр по программе

**Проблема:** Нельзя отфильтровать события по конкретной программе/курсу.

**Решение:**
- API: добавить `?program=` в `GET /api/deadlines`
- Frontend: селект/дропдаун с уникальными `program_title` из загруженных событий

**Приоритет:** низкий, после стабилизации.
