# Модуль генерации конспектов — SPEC

## User Story

Как студент Netology, я захожу в StudyCore и вижу на главной странице блок «Недавние конспекты». Если я ещё не создавал конспектов, система предлагает сгенерировать первый. На странице «Конспекты» я вижу все свои конспекты, могу искать по названию и содержанию, фильтровать по программе и модулю, а также изучать граф знаний.

При создании нового конспекта я выбираю программу → дисциплину/модуль → вебинар. Система берёт VTT-субтитры этого вебинара, генерирует структурированный конспект через LLM в фоновом режиме и сохраняет его в базе данных. Я могу открыть конспект, прочитать его и отредактировать при необходимости.

## Goals

1. Пользователь может генерировать конспекты из вебинаров Netology в 3 клика.
2. Генерация происходит в фоне — пользователь не ждёт у экрана.
3. Конспекты структурированы, хранятся в БД и доступны для поиска/редактирования.
4. Минимальная стоимость генерации за счёт VTT (бесплатно) + extractive preprocessing + дешёвых LLM.
5. Пользователь видит связи между конспектами через граф знаний.

## Non-Goals (MVP)

1. Обработка PDF, DOCX, PPTX — не делаем.
2. Обработка видео без VTT-субтитров — не делаем.
3. Локальный Whisper / Ollama / GPU — не используем.
4. Совместный доступ / шеринг конспектов — не делаем.
5. Автоматическая генерация всех конспектов сразу — только on-demand по одному.
6. Мобильное приложение вне Telegram Mini App — не делаем.

## Risks

| Риск | Вероятность | Влияние | Митигация |
|------|-------------|---------|-----------|
| Kinescope меняет HTML-структуру → VTT не извлекается | Средняя | Высокое | Fallback: сообщение «субтитры не найдены», мониторинг |
| OpenRouter API недоступен или rate limit | Средняя | Высокое | Retry logic, очередь с dead-letter, fallback модель |
| Конспект получается низкого качества | Высокая | Высокое | Structured output (Pydantic), редактирование пользователем, feedback loop |
| Длинный вебинар → много токенов → дорого | Средняя | Среднее | Extractive summarization перед LLM, chunking с overlap |
| Netology API меняет контракт | Низкая | Высокое | Изолировать API client, тесты на реальных ответах |

## Requirements

### Функциональные

| ID | Требование | Приоритет |
|----|-----------|-----------|
| REQ-001 | На главной странице отображается блок «Недавние конспекты» с 3 последними конспектами. Если пусто — CTA «Сгенерировать первый конспект». | Must |
| REQ-002 | Страница «Конспекты» отображает все конспекты пользователя с карточками (название, программа, модуль, дата создания). | Must |
| REQ-003 | Кнопка «Создать конспект» открывает модальное окно с пошаговым выбором: программа → модуль/дисциплина → вебинар. | Must |
| REQ-004 | В списке вебинаров показываются только items типа `video` или `webinar`, у которых есть `video_url` и успешно извлекаются VTT-субтитры. | Must |
| REQ-005 | При выборе вебинара создаётся фоновая задача на генерацию конспекта. Пользователь видит статус (queued / extracting / generating / ready / failed). | Must |
| REQ-006 | Сгенерированный конспект сохраняется в PostgreSQL: заголовок, содержимое (структурированный Markdown/JSON), метаданные, raw VTT. | Must |
| REQ-007 | Пользователь может открыть конспект и редактировать его содержимое. Изменения сохраняются в БД с timestamp. | Must |
| REQ-008 | На странице «Конспекты» есть граф знаний (Obsidian-style): узлы — программы/модули/конспекты, рёбра — связи по принадлежности. | Should |
| REQ-009 | Поиск по конспектам ищет по названию и содержанию (full-text search PostgreSQL). | Must |
| REQ-010 | Фильтры по программе и модулю/дисциплине на странице конспектов. | Must |
| REQ-011 | Оптимизация токенов: VTT → очистка → extractive summarization (BERT/LexRank, локально) → LLM final summary. | Must |
| REQ-012 | LLM возвращает структурированный ответ (Pydantic), включающий: topic, summary, key_points, definitions, difficulty. | Must |

### Нефункциональные

| ID | Требование |
|----|-----------|
| REQ-NF-001 | Время генерации конспекта для 60-минутного вебинара ≤ 3 минут (при нормальной нагрузке). |
| REQ-NF-002 | Стоимость генерации одного конспекта ≤ $0.10 (за счёт VTT + extractive + дешёвой модели). |
| REQ-NF-003 | UI отзывчивый: фильтры и поиск с debounce, skeleton при загрузке. |
| REQ-NF-004 | Очередь задач надёжна: retry 3x, dead-letter queue для failed jobs. |

## Acceptance Criteria

1. Пользователь заходит на главную — видит пустой блок «Недавние конспекты» с кнопкой «Создать первый конспект».
2. Нажимает кнопку → открывается модалка → выбирает программу → модуль → вебинар.
3. После выбора вебинара модалка закрывается, появляется toast «Конспект генерируется».
4. Через 1–3 минуты конспект появляется в списке со статусом «Готов».
5. Пользователь открывает конспект — видит структурированный текст с заголовками, ключевыми моментами, определениями.
6. Пользователь редактирует текст → нажимает «Сохранить» → изменения persist в БД.
7. Пользователь вводит в поиск «инфляция» — находит конспекты, где это слово есть в содержании.
8. Пользователь выбирает фильтр «Программа X → Модуль Y» — список обновляется.
