## Что сделано

### 1. Backend — endpoint для одного курса

**Файл:** `backend/api/programs_router.py`

**Новый endpoint:** `GET /api/programs/{program_id}`

```python
@router.get("/programs/{program_id}", response_model=CourseResponse)
async def get_program(
    program_id: int,
    session: UserSession = Depends(get_current_session),
):
    """Вернуть одну активную программу по ID с прогрессом."""
    service = NetologyProgramsService()
    courses = service.get_active_courses(session.cookies_json)
    for course in courses:
        if course["id"] == program_id:
            return course
    raise HTTPException(status_code=404, detail="Курс не найден")
```

**Зачем отдельный endpoint:**
- Прямой заход по URL `/course/59690` работает (F5, ссылка из закладок)
- REST-конвенция — получение одного ресурса по ID
- В будущем можно расширить (описание курса, даты, дедлайны по модулю)

### 4. Frontend — hook `useCourse.ts`

**Файл:** `frontend/src/hooks/useCourse.ts`

```typescript
export function useCourse(programId: string | undefined) {
  const [course, setCourse] = useState<Course | null>(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState<string | null>(null);

  useEffect(() => {
    fetch(`http://localhost:8000/api/programs/${programId}`, {
      credentials: "include",
    })
      .then(...)
      .then((data: Course) => { setCourse(data); setLoading(false); })
      .catch((err) => { setError(err.message); setLoading(false); });
  }, [programId]);

  return { course, loading, error };
}
```

## 9. Frontend — React Query (кэширование на фронтенде)

**Файл:** `frontend/src/App.tsx`

Установлен `@tanstack/react-query` и настроен `QueryClient`:

```tsx
const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 5 * 60 * 1000,    // 5 минут — данные считаются свежими
      gcTime: 10 * 60 * 1000,      // 10 минут — храним в памяти после размонтирования
      refetchOnWindowFocus: true,  // обновляем при возврате на вкладку
      retry: 1,                    // 1 повторная попытка при ошибке
    },
  },
});
```

**Файл:** `frontend/src/hooks/usePrograms.ts`

Переписан на React Query:
```typescript
export function usePrograms() {
  const { data: courses, isLoading: loading, error } = useQuery({
    queryKey: ["programs"],
    queryFn: fetchPrograms,
  });
  return { courses: courses ?? [], loading, error: error?.message ?? null };
}
```

**Файл:** `frontend/src/hooks/useCourse.ts`

```typescript
export function useCourse(programId: string | undefined, initialData?: Course) {
  const { data: course, isLoading: loading, error } = useQuery({
    queryKey: ["course", programId],
    queryFn: () => fetchCourse(programId!),
    enabled: !!programId,
    initialData,  // если переданы данные из Home — не делаем запрос
  });
  return { course: course ?? null, loading, error: error?.message ?? null };
}
```

**Эффект:**
- При переходе Home → CourseDetail — данные мгновенные (из кэша React Query)
- При возврате на Home — курсы уже загружены, спиннера нет
- При возврате на вкладку после обучения на Netology — фоновое обновление прогресса

### 11. Backend — кэширование в PostgreSQL

**Файл:** `backend/models/session.py`

Добавлены поля в `user_sessions`:
```python
programs_cache_json: Mapped[Optional[dict]] = mapped_column(JSONB, nullable=True)
programs_cached_at: Mapped[Optional[datetime]] = mapped_column(DateTime(timezone=True), nullable=True)
```

**Alembic миграция:** `673585175e4d_add_programs_cache_to_user_sessions.py`

**Файл:** `backend/api/programs_router.py`

Логика `_get_programs_with_cache`:
1. Если кэш свежий (< 5 минут) — возвращаем из БД (0 запросов к Netology)
2. Если кэш устарел и rate limit OK — идём в Netology, обновляем кэш в БД
3. Если кэш устарел и rate limit сработал — возвращаем устаревший кэш (graceful degradation)
4. Если кэша нет и rate limit сработал — 429

**Результат тестирования:**
```
Запрос 1 (к Netology): 2.1 сек
Запрос 2 (из кэша):   0.005 сек
Запрос 3 (из кэша):   0.006 сек
Запрос 4 (из кэша):   0.005 сек
Запрос 5 (из кэша):   0.006 сек
```

### 12. Backend — rate limiting

**Файл:** `backend/api/programs_router.py`

In-memory rate limiter (без Redis):
```python
_netology_rate_limit: dict[str, float] = {}
RATE_LIMIT_SECONDS = 15.0  # не чаще 1 запроса к Netology в 15 сек
```

**Логика:**
- При каждом запросе к Netology записываем timestamp в словарь
- Если с последнего запроса прошло < 15 сек — rate limit сработал
- При сработанном rate limit: отдаём кэш (если есть) или 429

**Почему 15 секунд:**
- 1 запрос в минуту — слишком жёстко (пользователь может переключаться между курсами)
- 15 секунд — разумный компромисс: ~4 запроса в минуту максимум
- При нормальном использовании кэш TTL = 5 минут, так что реальных запросов к Netology будет 1 раз в 5 минут

## Технический долг (что надо доработать)

### 🔴 Модули для обычных курсов
Сейчас для курсов (не профессий) создаётся один «виртуальный» модуль с названием курса. Это временное решение, потому что:
- У курсов на Netology тоже могут быть несколько модулей
- Пользователь видит только один модуль и не понимает структуру курса

**Решение:** Исследовать структуру `/programs/progress` для курсов и решить: показывать реальные модули или оставить логику «один модуль = один курс».

### 🟡 Навигация «Назад»
Сейчас `navigate(-1)` — просто шаг назад в истории браузера. Если пользователь зашёл по прямой ссылке — вернётся на предыдущий сайт, а не на Home.

**Решение:** Использовать `navigate("/")` или проверять `location.state?.from`.

### 🟡 Свайп-жест
Запланирован, но не реализован. Можно добавить через библиотеку `react-swipeable` для мобильного UX.
